# Sonde Browser — Architectural Principles & Development Rules

Этот документ содержит ключевые выводы, архитектурные правила и инженерные стандарты, выработанные в процессе переноса и развития браузера Sonde 2.0 (переход с Python/PyQt6 на Rust/Wry/WebKitGTK).

---

## 1. Сборка и управление ресурсами системы

- **Лимит оперативной памяти (3.6 GB RAM)**:
  - На хосте доступно ограниченное количество ОЗУ. Параллельная компиляция (`cargo build --release`) в несколько потоков перегружает систему и приводит к аварийной остановке через Linux OOM-killer.
  - **Правило**: Всегда выполнять сборку с флагом `-j 1` (или максимум `-j 2`):
    ```bash
    cargo build --release -j 1
    ```
- **Встраивание ресурсов в бинарник (`include_str!`)**:
  - Все UI-файлы (`ui/index.html`, `ui/style.css`, `ui/main.js`, `ui/startpage.html`) и внутренние страницы (`resources/settings.html`, `resources/history.html`, `resources/downloads.html`) вкомпилируются прямо в исполняемый файл через `include_str!`.
  - Любые правки во фронтенде требуют пересборки бинарника и копирования в `~/.local/bin/sonde-rs`.

## 2. Сетевая архитектура и локальный прокси (`proxy.rs`)

- **Обход WebKit CSP и X-Frame-Options**:
  - WebKitGTK внутри `iframe` строго блокирует страницы с заголовками `X-Frame-Options: SAMEORIGIN / DENY` и строгой `Content-Security-Policy`.
  - Локальный прокси на `http://127.0.0.1:39281` вырезает эти заголовки и прозрачно доставляет контент во фрейм.
- **Поддержка SPA (YouTube, GitHub, Polymer, Turbo-Frame)**:
  - SPAs отправляют API-запросы с кастомными заголовками (`Content-Type: application/json`, `X-YouTube-Client-Name`, `X-Goog-*`, `Turbo-Frame`).
  - Прокси обязан пробрасывать **все** заголовки клиента и обязательно сохранять тело и `Content-Type` для `POST`, `PUT`, `PATCH`. Иначе YouTube отдаёт пустые серые скелетоны.
- **Потоковое видео и частичный контент (HTTP 206)**:
  - Видеоплееры и WebKit media stream требуют поддержки заголовка `Range`. Прокси обязан отдавать статус `206 Partial Content` с заголовками `Content-Range` и `Accept-Ranges: bytes`.
- **Защита от рекурсивных прокси-ссылок**:
  - Функция `parse_query_url` обязана рекурсивно разворачивать вложенные `/proxy?url=`, предотвращая циклические самовызовы и белый экран.
- **Чистый User-Agent**:
  - Не добавлять токены вроде `Sonde/2.0` к User-Agent для Google/YouTube: это провоцирует блокировки ботов и урезает JS-бандлы.

## 3. Адаптивность и интерфейс (`ui/`)

- **Приоритет адресной строки**:
  - Контейнер `.url-bar-container` должен иметь гарантированную ширину (`min-width: 130px; flex: 1 1 180px;`). При уменьшении окна он **никогда не должен сжиматься в ноль**.
- **Фиксация кнопок тулбара (`flex-shrink: 0`)**:
  - Все навигационные кнопки обязаны иметь `flex-shrink: 0`. Без этого flexbox сжимает их хитбоксы, приводя к смещению координат клика (нажатие на настройки активирует соседние команды).
- **Адаптивные брейкпоинты**:
  - `> 1180px`: Полные кнопки с текстом.
  - `880px - 1180px`: Компактные кнопки без текста (только иконки).
  - `< 880px`: Кнопки действий сворачиваются в меню переполнения **`⋯`** (`#btnNavOverflow`), сохраняя строку поиска на всю ширину.
- **Мобильный режим**:
  - Поля ввода `W:` и `H:` должны быть текстовыми (`type="text" inputmode="numeric"`), без нативных браузерных стрелок-ползунков.
  - Изменение значений в инпутах должно мгновенно масштабировать и центрировать фрейм без принудительного сброса на 100%.

## 4. Дизайн, стили и шрифты

- **Основной акцент**: Песочный оттенок Desert Sand (`#d4a373`), минималистичный моноширинный шрифт и строгая прямоугольная геометрия (0px border-radius).
- **Фон выпадающих элементов**:
  - Вспомогательные блоки (масштаб, аккаунт, обновления) должны использовать сероватый фон `var(--bg-elevated)` / `var(--bg-surface)`, а не инородный чёрный `#000`.
- **Безопасность и бейджи**:
  - Избегать цветных эмодзи в интерфейсе статусов. Использовать текстовые моноширинные бейджи: `[ЗАЩИЩЕНО]`, `[НЕБЕЗОПАСНО]`, `[СИСТЕМА]`.

---

## 5. Хранилище, безопасность и синхронизация

- **Пароли и автозаполнение**:
  - Данные хранятся в защищённой SQLite-базе `passwords`. Перехват форм авторизации выполняется через `postMessage` (`sonde_save_password_prompt` и `sonde_autofill_data`).
- **Синхронизация Cloudflare Workers**:
  - В меню и настройках заложено поле аккаунта и кнопка синхронизации с бейджем `[СКОРО]` для реализации в версии 2.1.0 на базе Cloudflare Workers KV/D1.
- **Проверка обновлений**:
  - Интегрирована проверка релизов через GitHub REST API (`qualbyy/sonde`) с кнопкой мгновенного перехода к загрузке обновления.

## 6. Git-стратегия, релиз и архивация легаси-версии (Python)

- **Активная ветка**: Ветка `rust-dev` является основной веткой активной разработки Sonde 2.0 (Rust/WebKitGTK).
- **План слияния и архивации старой версии (Crux/Python)**:
  1. **Создание архивной ветки для Python-версии**:
     - Перед заменой ветки `main` или непосредственно из коммита старой версии (`v1.3.7` / `f52791e`) создаётся отдельная архивная ветка (например, `legacy-python` или `crux-legacy`):
       ```bash
       git branch legacy-python f52791e
       git push origin legacy-python
       ```
     - В архивной ветке `legacy-python` файл `README.md` сокращается до необходимого минимума с явной плашкой о прекращении поддержки:
       > **⚠️ ВНИМАНИЕ: Данная версия браузера на Python/PyQt6 устарела и больше не поддерживается.**
       > Актуальная версия Sonde 2.0 на Rust доступна в ветке `main`.
  2. **Слияние `rust-dev` в `main`**:
     - Ветка `rust-dev` заменяет `main` через бескомпромиссный fast-forward merge:
       ```bash
       git checkout main
       git merge rust-dev --ff-only
       git push origin main
       git checkout rust-dev
       ```
  3. **Состояние репозитория после релиза**:
     - `main` — стабильная кодовая база Sonde 2.0 (Rust/Wry).
     - `legacy-python` (или `crux-legacy`) — зафиксированная архивная версия Crux v1.3.7 с минимальным README и пометкой о прекращении поддержки.
     - `rust-dev` — ветка для дальнейшей разработки версий 2.1.0+ (синхронизация Cloudflare Workers и др.).

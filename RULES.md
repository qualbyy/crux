# Sonde Browser — Architectural Principles & Development Rules

Этот документ содержит ключевые выводы, архитектурные правила и инженерные стандарты, выработанные в процессе переноса и развития браузера Sonde (переход с Python/PyQt6 на Rust/Wry/WebKitGTK).

---

## 1. Сборка и управление ресурсами системы

- **Лимит оперативной памяти (3.6 GB RAM)**:
  - На хосте доступно ограниченное количество ОЗУ. Параллельная компиляция (`cargo build --release`) в несколько потоков перегружает систему и приводит к аварийной остановке через Linux OOM-killer.
  - **Правило**: Всегда выполнять сборку с флагом `-j 1` (или максимум `-j 2`):
    ```bash
    cargo build --release -j 1
    ```
- **Встраивание ресурсов в бинарник (`include_str!`)**:
  - Все UI-файлы (`ui/index.html`, `ui/style.css`, `ui/main.js`, `ui/startpage.html`) и внутренние страницы (`resources/settings.html`, `resources/history.html`, `resources/downloads.html`) вкомпилируются прямо в исполняемый файл через `include_str!`.
  - Любые правки во фронтенде требуют пересборки бинарника и копирования в `~/.local/bin/sonde-rs`.

---

## 2. Сетевая архитектура и режимы подключения

- **Прямое подключение по умолчанию (`use_proxy = false`)**:
  - Встроенный WebKitGTK запускается с флагом `disable_web_security = true`, что позволяет загружать веб-ресурсы напрямую в контейнер без промежуточного проксирования.
  - Прямое подключение гарантирует работу YouTube (главная страница, превью, стримы, комментарии, Polymer API), GitHub (поиск, формы, Turbo-Frames) и всех современных веб-приложений на полной аппаратной скорости по нативным протоколам HTTP/2 и HTTP/3.
- **Опциональный локальный прокси (`proxy.rs`)**:
  - Прокси на `127.0.0.1:39281` является опциональным и отключен по умолчанию. Включается пользователем в настройках только при необходимости строгого вырезания CSP / frame-ancestors.
  - Адресная строка браузера обязана **всегда** отображать чистый целевой адрес: префикс `http://127.0.0.1:39281/proxy?url=` должен автоматически и безоговорочно разворачиваться функцией `unwrapProxyUrl()`.
- **Поддержка сжатия ответов (gzip, brotli, deflate)**:
  - HTTP-клиент прокси обязан автоматически распаковывать входящие сжатые данные, предотвращая появление нечитаемых символов ("кракозябр") в теле HTML.

## 3. Адаптивность и интерфейс (`ui/`)

- **Приоритет адресной строки**:
  - Контейнер `.url-bar-container` должен иметь гарантированную ширину (`min-width: 130px; flex: 1 1 180px;`). При уменьшении окна он **никогда не должен сжиматься в ноль**.
- **Фиксация кнопок тулбара (`flex-shrink: 0`)**:
  - Все навигационные кнопки обязаны иметь `flex-shrink: 0`. Без этого flexbox сжимает их хитбоксы, приводя к смещению координат клика.
- **Адаптивные брейкпоинты**:
  - `> 1180px`: Полные кнопки с текстом.
  - `880px - 1180px`: Компактные кнопки без текста (только иконки).
  - `< 880px`: Кнопки действий сворачиваются в меню переполнения `⋯` (`#btnNavOverflow`), сохраняя строку поиска на всю ширину.
- **Мобильный режим**:
  - Поля ввода `W:` и `H:` должны быть текстовыми (`type="text" inputmode="numeric"`), без нативных браузерных стрелок-ползунков.
  - Пресеты мобильных устройств включают современные складные и флагманские модели (Samsung Galaxy Z Fold Folded/Unfolded, Galaxy S24 Ultra, Galaxy Z Flip, iPhone, Pixel), исключая десктопные размеры.
- **Интерактивный перебинд горячих клавиш**:
  - Назначение горячих клавиш в настройках должно выполняться интерактивным перехватом нажатий клавиш (`keydown`), а не ручным вводом текста в инпуты.

## 4. Дизайн, стили и запрет эмодзи / ИИ-клише

- **Строгий запрет эмодзи**:
  - **Категорически запрещено** использовать эмодзи в любых файлах документации (README, спецификации), в коде и в интерфейсе браузера (HTML/CSS/JS).
  - Для статусов и индикаторов используются исключительно текстовые моноширинные бейджи (`[ЗАЩИЩЕНО]`, `[НЕБЕЗОПАСНО]`, `[СИСТЕМА]`, `[АКТИВЕН]`, `[СКОРО]`) либо векторная SVG-графика.
- **Запрет ИИ-клише и чужих брендов**:
  - Запрещено использовать шаблонные формулировки (например: "разработано с помощью...", "powered by..."), а также упоминания сторонних ИИ-компаний (Anthropic и других коммерческих брендов). Браузер позиционируется как независимый проект Sonde.
- **Основной акцент**: Песочный оттенок Desert Sand (`#d4a373`), минималистичный моноширинный шрифт и строгая прямоугольная геометрия (0px border-radius).
- **Фон выпадающих элементов**:
  - Вспомогательные блоки (масштаб, аккаунт, обновления) должны использовать сероватый фон `var(--bg-elevated)` / `var(--bg-surface)`, а не инородный чёрный `#000`.

## 5. Хранилище, безопасность и синхронизация

- **Пароли, автозаполнение и миграция**:
  - Данные хранятся в защищённой SQLite-базе `passwords`.
  - Поддерживается универсальный импорт/миграция паролей из других браузеров (Chrome, Firefox, Edge, Brave, Opera) через форматы CSV и JSON, а также прямой экспорт.
- **Мультиаккаунтные контейнеры**:
  - Вкладка настроек контейнеров обеспечивает полноценное управление профилями (Личный, Работа, Банкинг, Шопинг, Изолированный и пользовательские), выбор индивидуальных цветов и настройку изоляции хранилища.
- **Синхронизация Cloudflare Workers**:
  - В меню и настройках заложено поле аккаунта и кнопка синхронизации с бейджем `[СКОРО]` для реализации в версии 2.1.0 на базе Cloudflare Workers KV/D1.
- **Проверка обновлений**:
  - Интегрирована проверка релизов через GitHub REST API (`qualbyy/sonde`) с кнопкой перехода к загрузке обновления.

## 6. Git-стратегия, релиз и архивация легаси-версии (Python)

- **Активная ветка**: Ветка `rust-dev` является основной веткой активной разработки Sonde (Rust/WebKitGTK).
- **План слияния и архивации старой версии (Crux/Python)**:
  1. **Создание архивной ветки для Python-версии**:
     - Перед заменой ветки `main` или непосредственно из коммита старой версии (`v1.3.7` / `f52791e`) создаётся отдельная архивная ветка (например, `legacy-python`):
       ```bash
       git branch legacy-python f52791e
       git push origin legacy-python
       ```
     - В архивной ветке `legacy-python` файл `README.md` сокращается до необходимого минимума с явной плашкой о прекращении поддержки:
       > **[ВНИМАНИЕ] Данная версия браузера на Python/PyQt6 устарела и больше не поддерживается.**
       > Актуальная версия Sonde на Rust доступна в ветке `main`.
  2. **Слияние `rust-dev` в `main`**:
     - Ветка `rust-dev` заменяет `main` через бескомпромиссный fast-forward merge:
       ```bash
       git checkout main
       git merge rust-dev --ff-only
       git push origin main
       git checkout rust-dev
       ```
  3. **Состояние репозитория после релиза**:
     - В `main` остаются исключительно чистые исходники на Rust (`src-tauri/`, `ui/`, `resources/`, `build_linux.sh`, `build_windows.bat`, `build_wine.sh`).
     - Все устаревшие файлы Python-исходников (`*.py`, `*.qss`, `*.spec`, `dist/`, `build/`, `requirements.txt`) полностью исключены и перемещены в архивную ветку `legacy-python`.
     - `main` — стабильная чистая кодовая база Sonde (Rust/Wry).
     - `legacy-python` — зафиксированная архивная версия Crux v1.3.7 с минимальным README и пометкой о прекращении поддержки.
     - `rust-dev` — ветка для дальнейшей разработки версий 2.1.0+ (синхронизация Cloudflare Workers и др.).

## 7. Протокол локального прокси, CORS и маршрутизация SPA (YouTube / GitHub)

- **Корректность парсинга HTTP-заголовков**:
  - Чтение заголовков обязано строго останавливаться при достижении пустой строки (line.trim().is_empty() или 

). Любые последующие строки относятся к телу запроса (POST payload). Несоблюдение этого правила приводит к попаданию строк JSON-тела (содержащих двоеточия) в заголовки и падению с ошибкой InvalidHeaderName.
- **Стандарт CORS и учетные данные (Access-Control-Allow-Credentials: true)**:
  - По спецификации W3C CORS, если ответ содержит заголовок Access-Control-Allow-Credentials: true, заголовок Access-Control-Allow-Origin **ни при каких условиях не должен быть wildcard `*`**.
  - Сервер прокси обязан возвращать точный Origin из входящего запроса (или http://127.0.0.1:39281), иначе движок WebKit бракует ответ как небезопасный.
- **Перехват API-запросов в SPA-приложениях (window.fetch и XMLHttpRequest)**:
  - Современные SPA-платформы (YouTube Polymer, GitHub Turbo) отправляют динамические XHR/Fetch запросы (например, /youtubei/v1/browse, /youtubei/v1/search) с передачей заголовка Origin.
  - Встроенный в прокси инжектируемый скрипт обязан перехватывать вызовы window.fetch, XMLHttpRequest.prototype.open и navigator.sendBeacon, направляя их через локальный прокси с подстановкой аутентичных заголовков Origin и Referer целевого хоста. Это обеспечивает мгновенную загрузку превью-карточек, видеопотоков и результатов поиска.
- **Неблокирующее чтение тела POST-запросов**:
  - При чтении дополнительных чанков POST-тела из сокета должен использоваться короткий таймаут (500-600 мс), предотвращающий 12-секундное зависание при раннем закрытии соединения клиентом.
